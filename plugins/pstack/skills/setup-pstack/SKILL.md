# Setup pstack

Configure one portable model sheet for the current parent harness. Read [`provider-dispatch.md`](../poteto-mode/references/provider-dispatch.md) before probing or writing anything. Its descriptor grammar, harness policies, route table, and receipt contract are authoritative. Never ask for or store an endpoint, credential, header, executable path, or command template.

Claude Code writes `~/.claude/pstack-models.md` and loads it from `~/.claude/CLAUDE.md` with:

```text
@~/.claude/pstack-models.md
```

Codex writes `~/.codex/pstack-models.md`. Codex has no `@` include, so mirror the sheet's exact bytes inside one bounded block in `~/.codex/AGENTS.md` and retain the sheet as the editable source of truth:

```text
<!-- pstack:models:begin -->
<exact contents of ~/.codex/pstack-models.md>
<!-- pstack:models:end -->
```

## Steps

### 1. Establish the parent

Use the harness and tool surface running this skill: Claude Code or Codex. Environment markers may corroborate that top-level answer, but do not launch a child and ask it to detect where it came from. Record the parent because the same descriptor can take a different native or external route in each harness.

### 2. Load and normalize current state

Read the current parent-specific sheet when it exists. Treat a missing `Schema:` line as released schema 1. Normalize each schema 1 descriptor in memory before route matching:

- `claude:<model>@<effort>` becomes `claude[anthropic]:<model>@<effort>`.
- `codex:<model>@<effort>` becomes `codex[openai]:<model>@<effort>`.
- `grok:<model>@<effort>` becomes `grok[xai]:<model>@<effort>`.

Then normalize only the rolling-alias predecessors generated by earlier releases. A Claude model is migratable when it starts with `claude-fable-` or `claude-opus-` and the remaining revision contains only digits and hyphens. Replace that model in memory with `fable` or `opus`, preserving harness, API provider, effort, role, and lane order. Record every original and normalized descriptor for confirmation. Do not write during normalization.

Overlay the loaded rows on the complete first-run role map in step 6 so the next successful write restores any missing documented role. Preserve every valid schema 2 custom route. A duplicate or unknown role, an unknown schema 1 harness, a malformed `Schema:` line, or an unknown versioned Claude model is inconsistent state; stop and resolve it before probing.

### 3. Collect intended route changes

Show the normalized complete role map. On a first run, propose the schema 2 defaults in step 6. On a rerun, keeping every role, lane order, route, and effort is the default. Ask whether to keep that map or change named roles; apply only changes the operator names.

A role can use one descriptor, a comma-separated descriptor list, `inherit-parent`, or `auto`. A descriptor may select any model accepted by a supported harness/API-provider pair. Named custom API providers are available through Codex and Pi, for example:

```text
codex[gateway]:gpt-5.6-sol@max
pi[gateway]:gpt-5.6-luna@max
```

The provider ID must already exist in trusted user-level harness configuration. Claude relay routing remains `claude[anthropic]` and comes from the approved environment projection documented in `provider-dispatch.md`; Grok remains `grok[xai]` and owns its endpoint/auth configuration. Never ask for those values or copy them into the sheet.

Why and Reflect require the parent's live MCP surface. Keep their investigator, reviewer, and synthesizer roles on `inherit-parent` or `auto`. For panel roles, one lane runs per entry. List length is the fan-out count. `arena cross-judge pool` is a list from which Arena chooses a target different from the parent and base candidate when possible. `swarm workers` is the default for each worker unless a race assigns another descriptor.

### 4. Validate the intended map

Validate the complete in-memory map before any probe or write:

- Every documented role appears exactly once.
- Every non-alias value matches `<harness>[<api-provider>]:<model>@<effort>`.
- Parse effort from the last `@` and the API provider from the brackets; do not infer either from the model.
- Harness is exactly `claude`, `codex`, `grok`, or `pi`.
- API-provider ID starts with an alphanumeric character and otherwise contains only alphanumerics, dot, underscore, or hyphen.
- Model is non-empty. Preserve harness-owned characters such as `/` or an earlier `@`.
- Effort is exactly `low`, `medium`, `high`, `xhigh`, or `max`.
- Claude uses API provider `anthropic`; Grok uses `xai`; Codex and Pi accept a valid named provider.
- Pi is read-only only. Do not assign it to a lane that the calling workflow must run in `isolated-write`.

Refuse an unqualified model slug, an endpoint or credential field, an unsupported fixed-provider combination, or a malformed alias. Do not invent a precedence or fallback rule. Do not probe or write while any inconsistency is unresolved.

### 5. Probe every distinct target

Group identical `(harness, API provider, model, effort)` targets and run one tiny read-only marker probe per distinct target. Use a native probe only when the current parent primitive can select the exact route: Claude/Anthropic under Claude Code, or Codex/OpenAI under Codex. Every other target uses the external runner, including a named Codex provider under a Codex parent.

The external runner must receive the separate target fields, unique prompt/output/receipt paths, and no implicit timeout. A successful probe requires exit `0`, a non-empty marker output, and a schema 2 `complete` receipt whose `target` and `routeProof` match the request. Pinned Codex argv proves only the route requested from Codex, not a custom gateway's private upstream routing.

A failed probe writes nothing: report the failing descriptor, stop, and keep the active sheet plus parent integration bytes unchanged. Never substitute another harness, API provider, model, or effort.

### 6. Confirm the final map

Show every schema 1 and rolling-alias migration, the native/external route for each final descriptor, and the exact rendered sheet. Ask for confirmation before writing. `inherit-parent` and `auto` always validate, but say when they reduce panel diversity.

The first-run map is:

```markdown
# pstack model configuration

Schema: 2

Harness/API-provider-qualified per-role choices. Read the installed pstack provider-dispatch reference before dispatching a configured role. Every documented role remains present. `inherit-parent` and `auto` use the parent model natively and still count as one panel lane.

feature, refactoring: grok[xai]:grok-4.6@xhigh
bug-fix: codex[openai]:gpt-5.6-sol@max
perf-issue: codex[openai]:gpt-5.6-sol@max
hillclimb: codex[openai]:gpt-5.6-sol@max
judgment and prose: claude[anthropic]:fable@max
hardest tasks: claude[anthropic]:fable@max
how explorer: grok[xai]:grok-4.6@xhigh
how explainer: claude[anthropic]:fable@max
how critics: claude[anthropic]:fable@max, codex[openai]:gpt-5.6-sol@max, grok[xai]:grok-4.6@xhigh, claude[anthropic]:opus@xhigh
why investigators, synthesizer: inherit-parent
reflect tooling, judgment, divergent, synthesizer: inherit-parent
arena runners: claude[anthropic]:fable@max, codex[openai]:gpt-5.6-sol@max, grok[xai]:grok-4.6@xhigh, claude[anthropic]:opus@xhigh
arena cross-judge pool: claude[anthropic]:fable@max, codex[openai]:gpt-5.6-sol@max, grok[xai]:grok-4.6@xhigh, claude[anthropic]:opus@xhigh
swarm workers: grok[xai]:grok-4.6@xhigh
architect runners: claude[anthropic]:fable@max, codex[openai]:gpt-5.6-sol@max, grok[xai]:grok-4.6@xhigh, claude[anthropic]:opus@xhigh
interrogate reviewers: claude[anthropic]:fable@max, codex[openai]:gpt-5.6-sol@max, grok[xai]:grok-4.6@xhigh, claude[anthropic]:opus@xhigh
```

Use this map only on a first run. On a rerun, preserve the normalized map unless the operator explicitly changes it.

### 7. Write both targets atomically

Render the sheet and parent integration in memory before either write. Snapshot every target's current bytes. Write only after every distinct probe passes and the operator confirms.

On Claude Code, keep exactly one `@~/.claude/pstack-models.md` include. On Codex, replace the complete bounded block in `~/.codex/AGENTS.md`; insert one block at the end on first run. If either marker is missing, duplicated, or reversed, stop instead of guessing a boundary.

Read both targets back and compare them with the in-memory render. If either write or readback fails, restore every snapshot and report the failure. An unchanged rerun must produce byte-identical schema 2 output. Do not copy a sheet between parent harnesses without rerunning the parent-specific probes.

### 8. Run a behavioral smoke

Run one small read-only mixed panel from this parent using the configured targets, distinct output/receipt paths, and an independent cross-judge. Launch native agents and external processes in one fan-out phase with retained handles, then drain all of them before judging. Verify native transcript metadata and every external schema 2 receipt. A structural configuration check or unit test is not a substitute.

Report the sheet path, normalized migrations, route table, distinct-target probes, smoke results, and external elapsed/token/cost receipt fields. Do not claim that requested effort or pinned argv exposes a provider's hidden execution or routing.
